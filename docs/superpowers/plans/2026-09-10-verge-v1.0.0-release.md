# Verge v1.0.0 Full Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a trustworthy v1.0.0 release with explicit platform tiers, verified native behavior, safe Claude integration, reproducible signed packages, clear installation and removal, and synchronized public documentation.

**Architecture:** Preserve the existing `core -> tools -> presentation -> native surface` flow. Improve native platform contracts and release integration without adding another product surface or another approval provider. Each phase ends in a separately reviewable commit and must leave the three-platform CI green.

**Tech Stack:** Rust 2021, Win32 through `windows-rs`, X11 through `x11rb`, Swift 5.9/AppKit, Node.js observer contracts, PowerShell/Python native tests, GitHub Actions.

**Spec:** `PRODUCT.md`, `DESIGN.md`, `docs/PRODUCT_ARCHITECTURE.md`, `docs/design/PORTABILITY.md`, and `SECURITY.md`.

## Global Constraints

- Windows release tier: Windows 11 x64, native Win32 surface, full session/usage behavior, and Claude direct approval.
- Linux release tier: Ubuntu 24.04 x86_64 under X11 or XWayland; native Wayland is explicitly unsupported in v1.0.0.
- macOS release tier: macOS 13 or newer on Apple silicon; Intel is explicitly unsupported in v1.0.0.
- Swift/AppKit is the authoritative macOS surface implementation; Rust remains the domain/presentation bridge through `verge-state`.
- Direct approval remains Claude-on-Windows only.
- Keep missing, malformed, stale, or unsupported readings explicit; never substitute zero or an inferred state.
- Keep Inter, current geometry, official provider names/colors, permission replacement, and 30-second inactivity collapse.
- No settings screen, dashboard, history, analytics, forecasting, cost estimates, sound alerts, session manager, new provider, or updater service.
- A portable package plus documented install/update/remove steps is sufficient for v1.0.0.
- Do not publish binaries until licensing/distribution terms are selected and signing credentials are configured.
- Every phase uses synthetic fixtures; real account files and real permission actions must not enter tests or artifacts.

## Integration order

```text
Support contract
  -> licensing decision
  -> capability matrix
  -> Windows display handling
  -> Linux X11 completion
  -> macOS native verification
  -> Claude install/recovery
  -> signed packaging
  -> soak/security certification
  -> v1.0.0 release
```

Windows, Linux, and macOS implementation phases may be developed independently after Phase 3, but they merge one at a time and re-run the full portable workflow after each merge. Packaging begins only after all platform phases pass. The release tag is created only after licensing, signing, verification, and documentation gates are complete.

## Explicitly deferred beyond v1.0.0

- Native Wayland/layer-shell.
- Codex, Linux, or macOS direct approvals.
- Automatic/background updates.
- Settings or detail application.
- Usage history, analytics, costs, predictions, or exports.
- Sound, flash, OS notifications, terminal-focus tracking, or inferred stalled state.
- Multi-account controls and session-management actions.
- New provider integrations beyond maintaining the observers already shipped.
